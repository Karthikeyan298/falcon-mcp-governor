The challenge

AI agents need guardrails.
Your business needs control.

AI agents are increasingly powerful — and increasingly connected to sensitive business systems. Without governance, that's a significant and growing risk.

🔓

Unchecked access

Agents can call any tool on any system they're connected to — email, databases, APIs — with no policy enforcement between them and your data.

🕵️

No audit trail

If an agent takes a destructive action, there's no record of what was called, with what arguments, by which agent identity.

⚡

Runaway automation

Agents in a loop can generate thousands of tool calls in minutes — flooding downstream systems or causing unintended consequences at scale.

📋

Compliance gaps

Regulators increasingly expect controls on automated systems. Agents acting on your behalf without human-in-the-loop controls create audit and compliance risk.

How it works

A single control plane for all your AI agents.

Falcon sits between your AI agents and the tools they use. Every call passes through the gateway — enforcing policy, logging decisions, and detecting anomalies in real time.

1

Agent authenticates

Each agent has a unique cryptographic API key. Falcon verifies the identity before any tool call is evaluated — self-reported identities are never trusted.

2

Policy is evaluated

The call is checked against your governance policy — who is allowed to call what, with what arguments, under what conditions. Rules are granular to the parameter level.

3

Decision is enforced & logged

The call is allowed, blocked, or held for human approval. Every decision is written to an immutable audit trail — no exceptions.

4

Anomalies are detected

Falcon monitors call patterns in real time. Denial spikes, unusual call volumes, new tool attempts, and approval floods trigger immediate alerts to your security team.

Capabilities

Everything you need to govern AI agents.

Six core capabilities work together to give your security, compliance, and operations teams complete visibility and control.

🛡️

Granular Policy Engine

Define exactly what each agent is allowed to do — per tool, per server, per argument value. Policies are version-controlled YAML, deployable in seconds.

  • Allow, deny, or require approval per tool
  • Argument-level rules (e.g., block external email recipients)
  • Per-agent policy overrides for privileged agents
  • Wildcard rules for blanket default-deny postures
  • Instant deploy — no restarts, no downtime
✅

Human-in-the-Loop Approvals

Mark sensitive operations as requiring admin sign-off before they execute. The agent waits; the human decides; the action runs only when approved.

  • Configurable per-tool approval requirement
  • Admins see agent identity, tool, and full arguments
  • Policy is re-evaluated at execution time — no stale approvals
  • Deny flow logs a full audit entry and triggers anomaly detection
  • Real-time pending count badge for reviewers
📋

Immutable Audit Trail

Every policy decision — allow, deny, pending, execute — is written to an append-only log with agent identity, tool, arguments, user, timestamp, and reason.

  • 100% decision coverage — no calls bypass the log
  • Tamper-evident append-only design
  • Exportable as JSON for SIEM integration
  • Policy deployments are also logged
  • Per-user attribution via optional agent user header
🔔

Real-time Anomaly Detection

Falcon continuously monitors call patterns and raises alerts the moment suspicious behavior is detected — before it becomes an incident.

  • Denial spike detection (possible probe or misconfiguration)
  • Call rate flood detection (possible runaway loop)
  • First-ever tool attempt alerts (shadow IT discovery)
  • Approval flood detection
  • Configurable thresholds, windows, and severity levels
🔑

Zero-Trust Agent Identity

Every agent is registered with a cryptographic API key. Falcon resolves identity from the key — never from anything the agent self-reports. Compromised or rogue agents can be suspended instantly.

  • One-way key hashing — raw keys never stored
  • One-click global agent suspension
  • Dynamic "tools allowed" count per agent under live policy
  • Tool visibility filtered per-agent — denied tools are hidden
🔍

Tool Trust Registry

Every MCP tool is registered and verified before it can be called. Unverified tools are blocked at the registry level, before policy is even consulted.

  • Auto-discovery on server sync
  • Verified / Needs review / Revoked trust levels
  • Revoked tools blocked even if policy says allow
  • Tool risk and environment classification
  • Tool policy matrix — visual per-agent access view
Use cases

Built for real governance scenarios.

Falcon is deployed in environments where AI agents touch business-critical systems.

Financial Services

AI agents with access to payment and transaction systems

Require human approval before any agent initiates a payment or modifies account data. Audit every query. Alert on unusual access patterns. Meet SOC 2 and PCI-DSS documentation requirements.

SOC 2 PCI-DSS Approval workflow
Healthcare

AI agents accessing patient records and clinical systems

Policy restricts agents to reading only the records they are authorized for. Parameter rules block queries outside a patient's assigned care team. Every access is logged for HIPAA audit readiness.

HIPAA Parameter rules Audit trail
Enterprise IT

AI agents running infrastructure operations

Default-deny policy with explicit allow lists for safe read operations. Any destructive action (delete, restart, scale-down) requires human approval. Anomaly detection catches runaway automation before it cascades.

Default deny Anomaly detection Human approval
Customer Operations

AI agents sending emails and managing CRM data

Parameter rules block outbound email to external domains without approval. Per-agent policy ensures the support agent can read tickets but not delete them. The sales agent can update records but not export the full database.

Email governance Per-agent policy CRM protection
Legal & Compliance

AI agents reviewing documents and filing systems

All document access is logged with agent identity and timestamp. Agents cannot delete or modify privileged documents without an approval chain. Audit export gives legal teams instant access to complete AI activity records.

e-Discovery Privilege protection Audit export
Software Development

AI coding agents with access to repositories and CI/CD

Agents can read code and open pull requests, but cannot push to main or trigger production deployments without human sign-off. New tool attempts are surfaced immediately so shadow IT is caught on day one.

Branch protection Shadow IT detection Deploy gates

Deployment

Runs wherever you need it.

Falcon is open source, self-hosted, and designed to run in your infrastructure — your data never leaves your environment.

🐳 Docker Compose

The fastest path to a running instance. One command brings up the backend, UI, and database with sane defaults.

  • Production-ready in minutes
  • Persistent SQLite volume for data durability
  • Environment variables for all configuration
  • Suitable for team deployments and internal tools

☸️ Kubernetes / Cloud

Deploy the backend and UI as container workloads. Replace SQLite with a managed database for high-availability scenarios.

  • Stateless backend — scale horizontally
  • Configurable CORS origins for any domain
  • Works behind any reverse proxy or API gateway
  • Compatible with standard secret management (Vault, AWS Secrets Manager)
